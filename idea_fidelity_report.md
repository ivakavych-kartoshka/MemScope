# MemScope idea fidelity report

Canonical source: `idea.pdf` (five pages), cross-checked against its source file `idea.tex` and a rendered first-page preview on 2026-10-03.

## Extracted idea

1. **Exact working title:** *MemScope: A Purpose-Bound Memory Service for Mobile Personal Agents*.
2. **Core field:** mobile systems security and privacy; on-device persistent memory for LLM-based personal agents; Android OS services.
3. **Core technical keywords:** purpose limitation, persistent agent memory, provenance, lifetime/TTL, consumer/app/tool scope, retrieval token, reference monitor, label propagation, derived memory, AppSearch PlatformStorage, AppFunctions, policy-aware eviction, hardware-backed compartments.
4. **System entities:** Android `system_server`; MemScope system service; AppSearch-derived scoped store; token issuer; AppFunctions execution context; personal-agent application and Agent SDK; agent model; source apps/channels; third-party tools/AppFunctions providers; user; optional cloud model/backend; hardware-backed key store; attacker.
5. **Main mathematical objects:** a memory document and its payload; provenance tuple; purpose and consumer sets; sensitivity class; acquisition/expiry times; retrieval context/token; authorization predicate; a meet/intersection operator for derived labels; a derivation/source DAG; a candidate set and an authorized pre-ranking view; access log; eviction score/budget.
6. **Proposed algorithm/service name:** **MemScope**. Named components are Scoped Store, Retrieval Monitor, Label Propagator, Token Issuer, and Agent SDK. The source does not give a separate algorithm acronym, so the manuscript must not invent one as the central method.
7. **Theorem directions implied by the idea:** (i) reference-monitor admission soundness under trusted mediation and authentic tokens; (ii) monotone restriction of derived labels under meet propagation; (iii) cross-scope non-disclosure for returned plaintext under complete mediation; (iv) expiry safety at retrieval; (v) bounded filtering/label-meet cost. These directions are to be stated under explicit assumptions and must not be promoted into semantic non-inference or end-to-end confidentiality claims.
8. **Experiment plan:** AOSP implementation on Pixel 8/9 and a Samsung device; on-device labeling with Gemma 3n or a Qwen 0.5B-class model; multi-session assistant workloads spanning messaging, calendar, health, and shopping; ProfileFoundry/PersonaChat-style profiles; LoCoMo, LongMemEval, Memora, PA-Bench, and MemGUI-Bench where accessible and license-compatible; SPORE, MINJA, MEXTRA, ADAM, and MemPoison stress tests; latency, storage, energy, label errors, out-of-scope retrieval, extraction yield, utility, and safety-critical retention; ablations over label dimensions, derived-item verification, and policy-aware eviction.
9. **Baseline methods:** Mem0/Letta identity namespaces; Android AppSearch schema-type visibility; GAAP-style IFC without MemScope's memory labels; prompt-only privacy instructions; unscoped agent memory. The idea also names MobiMem's 23.8 ms retrieval figure as a contextual implementation target, not a result achieved by MemScope.
10. **Seed references:** Audience-Bound Persistent Memory (arXiv:2609.36373); MNC (arXiv:2608.01719); Memory as a Service (arXiv:2506.22815); GAAP (arXiv:2604.19657); MemPrivacy (arXiv:2605.09530); Mi-Memory (arXiv:2607.18975); DP-MemView (arXiv:2608.03130); SSGM (arXiv:2603.11768); MEXTRA; MINJA (arXiv:2503.03704); ADAM (arXiv:2604.09747); SPORE (arXiv:2607.23444); MemPoison (arXiv:2605.29960); Android AppSearch/AppFunctions/AICore; Samsung KEEP; Microsoft Recall; Gemini Personal Intelligence; Riverbed; Vanish; MobiMem; ToolPrivacyBench; PiSAs; Memora; LoCoMo; LongMemEval; PA-Bench; ProfileFoundry; PersonaChat; MemGUI-Bench.
11. **Explicit risks/assumptions:** concurrent work may narrow novelty; policy defaults may be difficult to specify; source attribution/derived-item verification is imperfect; semantic inference can remain even when item admission is correct; narrow scopes can reduce utility; an attack operating wholly inside an authorized scope is not prevented; complete mediation and trustworthy OS/token issuance are necessary; physical compromise while a device is unlocked, covert channels, model-provider behavior after an authorized disclosure, and side-channel resistance are outside the core guarantee.
12. **What the paper is not about:** it is not a general cloud memory architecture, a prompt-only guardrail, a new foundation model, a differential-privacy mechanism, a federated-learning paper, an incentive/mechanism-design paper, a general-purpose Android ACL redesign, or a claim that labels eliminate semantic inference. It does not report completed benchmark results unless verifiable artifacts exist.

## LOCKED PAPER SPECIFICATION

- **Locked topic:** an Android OS-enforced, purpose-bound persistent memory service for mobile personal agents.
- **Locked problem statement:** preserve useful cross-session agent memory while ensuring that only memory items authorized for the active app, tool, purpose, consumer, and lifetime enter retrieval/ranking, including conservative propagation of restrictions to derived summaries and reflections.
- **Locked method family:** a system-owned labeled document store plus authenticated task-scoped retrieval tokens, complete reference-monitor mediation, meet-based derived-label propagation, verified source attribution, retrieval-time TTL checks, encrypted compartments, and policy-aware eviction.
- **Locked theoretical goals:** prove admission soundness, label monotonicity, returned-plaintext cross-scope non-disclosure under complete mediation, expiry safety, and transparent complexity bounds. Explicitly exclude unrestricted semantic non-inference and claims about data already legitimately disclosed to a compromised consumer.
- **Locked experiment family:** on-device Android implementation and mobile measurements; memory-utility benchmarks; multi-app workloads; published memory extraction/poisoning attacks; privacy/utility/overhead/energy/retention metrics; component and label-dimension ablations. Until runs exist, all outcomes are protocols or clearly marked placeholders.
- **Locked baseline family:** unscoped memory; Mem0/Letta namespace scoping; AppSearch visibility; prompt-only privacy; GAAP-style information-flow mediation; relevant audience/scope-bound memory systems when executable artifacts permit.
- **Terms that must appear in title/abstract/introduction:** MemScope; purpose-bound; memory service; mobile personal agents; on-device/Android; persistent memory; provenance; lifetime/expiry; app/tool scope; retrieval monitor; derived-memory label propagation.
- **Terms that must not dominate unless supported by the idea:** differential privacy; blockchain; federated learning; incentives; mechanism design; generic multi-agent coordination; cloud-only retrieval-augmented generation; model training. DP may appear only as a boundary/complement for cumulative inference.

## Fidelity decision

The source project contains only the concept PDF and its LaTeX source, so no experimental result files or prior paper draft exist. The manuscript must therefore present a rigorous design, formal safety properties, implementation plan, and evaluation protocol; it must not fabricate performance, attack-reduction, energy, accuracy, or statistical results.
